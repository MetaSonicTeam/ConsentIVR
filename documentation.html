ConsentIVR Documentation

A consent-first voice & SMS platform built on Flask, Twilio and SQLite. Inbound IVR routing, outbound appointment reminders and surveys, an operator dashboard, and compliance controls enforced in code.

Overview

ConsentIVR runs a call-center "front door" (inbound IVR) and opt-in outbound campaigns (voice and SMS). Operators monitor and control it from a web dashboard, with optional Telegram alerts. Everything is data-driven: menus, business hours, campaigns and recipients live in the database and are editable without code changes.

Inbound IVR

Menu-driven routing, warm transfer to agents, voicemail, and a global inbound mode switch.

Outbound campaigns

Appointment reminders & surveys over voice or SMS, dialing only consented, non-suppressed contacts.

Dashboard

Calls, live IVR events, menus, consent/opt-outs, campaigns, survey results, and the SMS message log.

Compliance

Signed webhooks, opt-out gating, recording disclosure, PGP exports, and optional at-rest DB encryption.

Design principles

These rules are enforced in code, not just documented:

  1. No identity-secret capture. There is no prompt, route, or database column for OTPs, SSNs, card numbers, or passcodes. The only digit the IVR interprets is a single menu selection (or a survey answer).
  2. Truthful identity. Prompts speak your real organization name (settings.ini [org] name). Caller ID is a Twilio number you own — there is no number-spoofing configuration.
  3. Consent before outbound contact. Outbound dialing lists are built only from contacts with a granted consent record (consent.callable_contacts).
  4. Always honor opt-out. A suppression / Do-Not-Call list is checked before every outbound call or text, and callers can opt out by keypress (voice) or STOP (SMS).
  5. Recording off by default, and when enabled the caller hears the recording notice before any audio is captured.
  6. Authenticated webhooks. Every Twilio webhook is verified with the X-Twilio-Signature (security.py).
You remain responsible for complying with the telemarketing, calling-time, recording-consent, and privacy laws that apply to you (e.g. TCPA, state two-party-consent recording laws, local equivalents).

Quick start

cd ConsentIVR
python -m venv .venv && . .venv/Scripts/activate     # Windows
pip install -r requirements.txt

cp .env.example .env         # edit with Twilio creds + PUBLIC_BASE_URL
python seed.py               # starter 'main' menu + business hours
python create_admin.py admin "a-strong-password"
python seed_campaign.py      # (optional) demo reminder + survey campaigns

python app.py                # dev server on http://localhost:5000

Expose it to Twilio in development with ngrok and point your number's webhooks at your PUBLIC_BASE_URL (see Twilio webhooks). Dashboard: http://localhost:5000/ · Health: /healthz.

Production: run under a WSGI server — gunicorn "app:create_app()" on Linux, or waitress on Windows.

The SMS status callback (/sms/status) is set automatically on each outbound message. Internal TwiML endpoints (/ivr/whisper, /ivr/post-call, /ivr/out/*) need no configuration — Twilio reaches them via PUBLIC_BASE_URL.

Inbound IVR call flow

Twilio -> POST /ivr/inbound
  check inbound mode (ivr | forward | voicemail | closed)
  if ivr:
    business hours?  no  -> after-hours message -> optional voicemail
                     yes -> play entry menu greeting, <Gather> 1 digit
         -> POST /ivr/menu/<key>
              digit -> dial(warm transfer) | submenu | voicemail | message | optout | repeat | hangup

Menus & option actions

Menus live in ivr_menus / ivr_options and are editable from the dashboard (IVR Menus), including each menu's greeting, after-hours message, voice, recording toggle, and active flag. Each keypad option has an action type:

action_typeBehavior
dialWarm-transfer the caller to action_value (whisper to agent, caller can press * to leave).
submenuJump to another menu (action_value = its menu_key).
voicemailRecord a message (only if recording is enabled; disclosure spoken first).
messageSpeak action_value, then return to the entry menu.
optoutAdd the caller to the opt-out list and confirm.
repeatReplay the current menu.
hangupThank the caller and end the call.

Inbound mode (global override)

A dashboard switch (IVR Menus → Inbound mode) changes how all inbound calls are handled immediately, without editing menus. The live value is stored in the settings table and re-read on every call.

ModeBehavior
ivrNormal menu flow (default).
forwardSend every call straight to a configured number (warm transfer). Overflow / emergency.
voicemailGo straight to the voicemail flow.
closedPlay a configured message and hang up.

Call transfer

  • Warm (attended) transfer. A dial option or forward mode plays a whisper to the agent (/ivr/whisper) before bridging; unanswered transfers fall back to voicemail.
  • Star to leave. The caller can press * during the agent call to pull out, landing on a short post-call menu ("press 1 to return to the main menu") rather than being dropped.
  • Outbound "press 0 for an agent". A reminder campaign with an agent_number lets recipients press 0 mid-call to be warm-transferred to a live agent (whisper, star-to-leave, "no one available" fallback). Voice reminders only.

Outbound campaigns

Create a campaign from Campaigns → New campaign: choose a kind (reminder / survey), a channel (voice / sms), the consent purpose it requires, a voice, the voicemail-detection toggle, and (voice) an optional agent number for "press 0". Then:

  • Add recipients — paste numbers (one per line; optional merge data after a comma becomes the {when} field, or paste a JSON object). The import is consent-checked: only consented, non-suppressed numbers are accepted; the rest are reported.
  • Launch / resume dials pending + failed recipients in the background, inside business hours. Pause stops after the current recipient.
  • Download results CSV (labels or raw digits for surveys).

Reminder scripts support {org} and per-recipient {when} (plus any keys in the recipient's vars_json). Unknown placeholders are left untouched.

Consent gates (re-checked at send time)

Every call/text passes three gates, re-checked per recipient at dial time — the import check is never trusted on its own:

  1. Not opted out (consent.is_opted_out).
  2. Has matching consent (consent.has_consent for the purpose; SMS requires consent granted for the sms channel specifically).
  3. Inside business hours (hours.is_open). Outbound fails closed: if no calling window is configured, nothing is dialed.

Background runner & cross-worker lock

Launches run in a background thread (jobs.py) so the web worker returns immediately; progress updates on refresh. A SQLite single-flight lock (job_locks, joblock.py) guarantees only one worker dials a given campaign at a time — safe even with several Gunicorn/Waitress workers. A crashed worker's lock goes stale after ~2 minutes and is reclaimable. Pacing is one recipient at a time with a short gap; it is not a burst dialer.

If you outgrow SQLite, move the runner to a dedicated queue (e.g. Redis + RQ); the dashboard only depends on jobs.launch() / jobs.is_running().

SMS reminders

SMS campaigns (reminder kind) send one text per recipient with a Reply STOP to opt out. footer. Inbound STOP/UNSUBSCRIBE writes an opt-out instantly; START re-subscribes. All messages are logged under Messages. SMS consent is distinct from voice consent — record it for the sms channel.

Surveys & results

Add questions to a survey campaign with an optional answer-label map (1=Poor, 2=Fair, 3=Good or JSON). On the call, each question gathers one or more DTMF digits. The campaign page shows a per-question breakdown with bars: defined choices always appear (even at 0 responses), and unexpected answers are listed after them. Export is label-aware by default; append ?raw=1 for the raw digits.

Consent & opt-out model

A contact becomes callable only with a granted consent record for the campaign purpose (or all) and no entry in opt_outs. Opt-out scope is all (suppresses everything) or a specific purpose. Numbers are canonicalized to E.164 on every read/write (consent.normalize_e164) so an opt-out typed as (415) 555-0123 reliably suppresses the stored +14155550123.

Inbound callers never need consent (they chose to call), but can always opt out by keypress. Operators manage opt-outs under Consent & Opt-outs.

Voices & voicemail detection

Prompts are spoken by an Amazon Polly voice. There is a global default (settings.ini), and each campaign and each inbound menu can override it from a curated list (US/UK/AU English, US Spanish) — each voice carries its own language automatically. Answering-machine detection (AMD) is a per-campaign toggle (default on): with it on, reminders are left as a voicemail message and surveys are not run against machines.

Security & privacy

  • Webhook authenticity. Every Twilio voice/SMS webhook is verified with X-Twilio-Signature (security.py); keep VALIDATE_TWILIO_SIGNATURE=1 in production.
  • Dashboard auth. bcrypt-hashed passwords, server-side sessions, role gates (admin / operator / viewer). Cookies are HttpOnly + SameSite=Lax.
  • PII masking. Telegram alerts mask phone numbers by default.
  • Audit log. Consent changes, logins, campaign actions and menu edits are recorded in audit_log.
Not yet included: CSRF tokens on dashboard POST forms (SameSite=Lax mitigates most cross-site POSTs) and login rate limiting. Add these before exposing the dashboard on the public internet.

Encryption (PGP exports & SQLCipher at rest)

PGP exports. Set PGP_PUBLIC_KEY_FILE to an ASCII-armored public key and result CSVs (which contain PII) download as .csv.pgp, openable only by the private-key holder. The server holds no private key, and a failed encryption aborts the export rather than leak plaintext. Requires the gpg binary.

At rest (SQLCipher). Set DB_ENCRYPTION_KEY and install a driver (pip install sqlcipher3) to encrypt the whole database transparently. If the key is set but no driver is installed, the app refuses to start rather than run unencrypted.

PGP is deliberately not used to encrypt phone-number columns: PGP ciphertext is non-deterministic, which would break opt-out exact-match suppression and the UNIQUE(phone_e164) constraint — silently letting opted-out people be dialed. Use SQLCipher (whole-DB) or full-disk encryption for at-rest protection.
-- Migrate an existing plaintext DB to encrypted:
sqlcipher consentivr.db
ATTACH DATABASE 'consentivr.enc.db' AS enc KEY 'your-passphrase';
SELECT sqlcipher_export('enc');
DETACH DATABASE enc;
-- then point DB_PATH at consentivr.enc.db

Compliance notes

This software provides controls (consent gating, opt-out, calling-window enforcement, recording disclosure, encryption) but does not by itself make you compliant.
  • TCPA / calling windows. Configure business hours; outbound fails closed when none are set. Keep SMS consent separate from voice consent.
  • Recording consent. Recording is off by default; the disclosure in [call] record_notice plays before any capture. Confirm one- vs two-party-consent rules for your jurisdictions.
  • Data protection. Encrypt exports (PGP) and the database (SQLCipher) or host disk, restrict dashboard access, and rotate credentials.
  • Honor opt-outs promptly. Opt-outs apply across voice and SMS and are checked before every outbound contact.
